# Data Model: MDF-e Source and Schema Baseline

This model describes the records required by the feature's evidence register and scope matrix. It is documentation-only; it does not define exported TypeScript types or generated XML models.

## Normative Source

One official publication or official state-operational source.

| Field                              | Meaning                                                                               | Validation                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `sourceId`                         | Stable identifier used by the source register                                         | Unique within the register                                                           |
| `publisher`                        | Issuing authority or portal owner                                                     | Required; distinguish CONFAZ, SVRS, RFB/SPED, and state Fazenda                      |
| `title`                            | Official title and act/publication identifier                                         | Required; preserve official version notation                                         |
| `sourceRole`                       | `normative`, `technical`, `operational`, `navigation`, or `secondary`                 | One value; only primary roles may establish feature requirements                     |
| `sourceStatus`                     | `current`, `historical`, `superseded`, `conflicting`, `inaccessible`, or `unverified` | Unknown applicability must not be labeled current without qualification              |
| `publishedAt`                      | Publication date, if stated                                                           | Nullable; do not infer from retrieval time                                           |
| `effectiveFrom` / `effectiveUntil` | Rule validity interval, if established                                                | Nullable; distinguish publication from legal effectivity                             |
| `consultedAt`                      | Date the source was checked                                                           | Required; this planning research uses 2026-10-12                                     |
| `urlOrPath`                        | Canonical official URL or repository capture path                                     | Required; captured pages remain linked to their live source where available          |
| `evidence`                         | Clause, section, row, package link, or quoted locator                                 | Required for every rule or route promoted to the scope matrix                        |
| `relations`                        | Amendment, supersession, correction, or package relationship                          | Each target must reference another registered source or explicitly remain unresolved |

## Schema Package

An official archive and its document/event schema contents, distinct from an XSD family generated by this repository.

| Field                | Meaning                                                                              | Validation                                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| `packageId`          | Official filename or stable package identifier                                       | Required and exact, including NT/revision suffix                                                                                   |
| `packageVersion`     | Package and referenced MOC/NT versions                                               | Required; do not collapse package revision and NT version                                                                          |
| `officialSourceId`   | Source-register owner of the download link                                           | Must reference a registered official technical source                                                                              |
| `publishedAt`        | Official publication date                                                            | Nullable only when the portal does not state one                                                                                   |
| `namespaceInventory` | Namespace URI and included document/event XSD entrypoints                            | Must be extracted from the actual official archive before code generation                                                          |
| `applicability`      | Effective start/end and covered environment/UF/operation, where officially supported | Unknown values remain `unverified`; do not substitute download date                                                                |
| `supersedes`         | Prior package/revision replaced or amended                                           | Must be sourced; partial overlays are not assumed to replace the base package                                                      |
| `integrity`          | SHA-256 digest and retrieval metadata for the inspected archive                      | Required for every inspected archive whether or not it is retained; without a digest, keep the package unverified                  |
| `baselineStatus`     | `candidate`, `verified`, `historical`, `conflicting`, `deferred`, or `unverified`    | `verified` requires source, contents, applicability, and supersession reconciliation; identity/content conflicts remain unverified |

## Service Route

One official service/environment route published by an authorizer.

| Field         | Meaning                                                 | Validation                                                                  |
| ------------- | ------------------------------------------------------- | --------------------------------------------------------------------------- |
| `routeId`     | Stable source-register key                              | Unique for the route tuple                                                  |
| `uf`          | Issuer UF or `national` where the catalog is shared     | A national SVRS endpoint does not itself prove every UF issuer is eligible  |
| `environment` | `homologation` or `production`                          | Must match the official catalog section                                     |
| `authorizer`  | Service authority, such as `SVRS`                       | Required                                                                    |
| `operation`   | Exact service name and version                          | Preserve catalog spelling and version                                       |
| `endpoint`    | Official URL                                            | Store the URL, not a resolved IP address                                    |
| `sourceId`    | Source-register record                                  | Must reference the official service catalog or applicable state instruction |
| `routeStatus` | `verified`, `candidate`, `conflicting`, or `unverified` | A general catalog entry cannot resolve an undocumented UF restriction       |
| `consultedAt` | Verification date                                       | Required; route availability may change independently of normative rules    |

## Initial Scope Matrix

One row for each proposed issuer/UF/environment/operation/schema/route combination.

| Field               | Meaning                                                               | Validation                                                                |
| ------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `issuerCohort`      | Explicit issuer category and any accreditation prerequisite           | Do not infer a complete cohort from high-level portal summaries           |
| `uf`                | Proposed issuer UF                                                    | SP remains a candidate until primary eligibility evidence is recorded     |
| `environment`       | Homologation or production                                            | Separate evidence and routes are required for each                        |
| `operation`         | Issuance, query, closure, cancellation, event, or distribution action | Each included action maps to a normative and/or official technical source |
| `schemaPackageId`   | Exact package/revision used by this operation                         | Must reference a verified package before runtime promotion                |
| `routeId`           | Official route, when a remote service is involved                     | Must reference the same UF/environment/operation tuple                    |
| `decision`          | `included`, `excluded`, `deferred`, or `unverified`                   | No item may be `included` with unverified required evidence               |
| `evidenceSourceIds` | Supporting source records                                             | Required for `included`; conflicts are listed, not silently resolved      |
| `contingency`       | `included`, `excluded`, or `unverified` plus reason                   | Default to `excluded` or `unverified` absent an official MDF-e procedure  |
| `readiness`         | `ready-for-runtime-spec` or `blocked`                                 | The runtime spec may advance only after all required rows are traceable   |

## Relationships and Invariants

- A schema package and service route reference one or more source records; source provenance is stored once in the source register and referenced by identifier elsewhere.
- A scope row may reference only registered packages and routes. It cannot turn a candidate or conflicting record into verified evidence.
- Legal effectivity and technical deployment are separate facts. A legal act's effective date does not prove a schema package was deployed, and an archive date does not establish legal applicability.
- Secondary sources and navigation pages may help locate primary sources but cannot be the sole evidence for an included requirement.
- The initial scope remains blocked if schema applicability, SP issuer eligibility, a required route, or a required lifecycle rule is unverified.
